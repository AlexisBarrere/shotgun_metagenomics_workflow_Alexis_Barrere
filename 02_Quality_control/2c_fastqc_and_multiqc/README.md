# Step 2c - FastQC and MultiQC
This step involved evaluating the quality of the sequencing reads before and after preprocessing, using `FastQC` for individual assessments and `MultiQC` for global summarization. FastQC was applied at multiple stages of the workflow : (i) after raw data download, (ii) after trimming, and (iii) after decontamination. This helped verify that trimming and decontamination effectively improved read quality.

## Execution
The quality control process was conducted in three successive phases, corresponding to major steps of the preprocessing workflow:
(i) after raw data acquisition, (ii) after read trimming, and (iii) after decontamination.

All analyses were performed using Bash scripts, and results were saved in dedicated subdirectories within the project structure.

Each script is listed below with the corresponding command and context of execution :

### (i) Raw reads
**Objective :** Evaluate the quality of the sequencing data prior to any preprocessing.  
1. `FastQC` was automatically run on all raw `.fastq` files (read1 and read2) from the 24 samples :  
```bash
run_fastqc_auto.sh
```

2. A global summary of the read quality was generated by aggregating all `FastQC` outputs using `MultiQC` :
```bash
run_multiqc.sh
```

⭢ These reports were initially generated in the directory `~/Stage_Copenhague/fastqc_results/`, then manually moved into `~/Stage_Copenhague/fastqc_pre_trimming/` to separate raw from processed results.

### (ii) Post-trimming reads
**Objective :** Assess whether trimming steps improved read quality and removed residual adapters or low-quality regions.
1. Trimming was first tested on sample 01 using `Trimmomatic` and `Fastp`. `FastQC` and `MultiQC` were applied afterward :
```bash
run_fastqc_multiqc_post_trim_sample01.sh
```

2. Once the trimming strategy was validated, `FastQC` was performed on all reads (paired and unpaired) from samples 01 to 24 :
```bash
run_fastqc_multiqc_post_trim_sample01_to_24.sh
```

3. As a final correction step, unpaired reads were re-trimmed to remove residual artifacts (adapters). A second round of `FastQC` was applied on these cleaned unpaired reads only, and the previous `MultiQC` report was replaced :
```bash
run_fastqc_multiqc_post_trim_sample01_to_24_final.sh
```

### (iii) Post-decontamination reads
**Objective :** Confirm that read quality remained high after the decontamination step. 
1. A final `FastQC` analysis was carried out on all decontaminated reads (paired and unpaired), and a comprehensive `MultiQC` report was generated :
```bash
run_fastqc_multiqc_post_trim_and_decontamination_all_samples.sh
```
⭢ This final report (`multiqc_report_post_trimming_and_decontamination.html`) provides an overview of the cleaned dataset and was used to validate the quality before proceeding to downstream steps.
